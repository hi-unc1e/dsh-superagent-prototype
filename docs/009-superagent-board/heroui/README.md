# HeroUI 可读性对照版

本目录是独立评审原型，不接入 DSH 插件、不运行真实任务、不调用 GitHub 或飞书。刷新会还原所有演示数据。

成品：[离线 HeroUI 版](../prototype-heroui.html)；对照：[原生 HTML 版](../prototype.html)。两个文件放在同一目录时，新版的“打开旧版对比”链接可用。

## 技术选择

- React 18.3.1 + HeroUI 2.8.10（本次使用 v2 API，不是最新 v3）。
- Tailwind CSS 3 + Vite 5；vite-plugin-singlefile 将资源合成一个离线 HTML。
- 实际使用 HeroUI 的 Card、Button、Tabs、Modal、Textarea、Accordion；不是手写 CSS 仿制 HeroUI。
- 框架提供组件与键盘/焦点基础；阅读体验来自信息取舍和字号，不由框架自动决定。

## 和旧版比较

| 项目 | 原生版 | HeroUI 对照版 |
| --- | --- | --- |
| 首页 | 触发流、任务、详情三栏 | 单栏工作概览，优先待判断 |
| 正文 | 多处 10–14px | 核心正文 18px，可切换为 21px；辅助文字 15–17px |
| 任务详情 | 常驻侧栏，完整时间线 | 点击打开弹窗，先结果与操作，过程默认折叠 |
| 颜色 | 多种状态、优先级与技术徽标 | 保留红色待判断、绿色通过、蓝色执行，减少徽标 |
| 实现成本 | 零依赖，但交互需手写 | 组件可复用，需要依赖和构建 |
| 离线成品 | 约 90KB | 约 0.9MB，内嵌 React 和组件运行时 |

此对比同时更换了布局和组件，不能把视觉改善全部归因于 HeroUI。正式采用与否应看可读性、交互一致性、后续开发成本。这里尚未把 HeroUI 引入现有 DSH 运行时。

## 可体验的操作

1. 查看待判断任务，点击绿色“通过”，任务移入已完成。
2. 点击“要改”，填写意见，任务回到等待队列。
3. 查看执行中任务，没有验收按钮。
4. “记一件事”添加到演示队列。
5. 固定流程可暂停、恢复、手动加入演示队列。
6. 切换更大字号，展开过程记录和等待资源。

## 构建

```sh
npm ci --registry=https://registry.npmjs.org
npm run build
cp dist/index.html ../prototype-heroui.html
```

主题扫描路径对应当前 lockfile 的嵌套安装位置；调整依赖版本后需核实路径。构建成功，但 Vite 配置转译会读取上层配置并提示 ES2024 target 警告；原型最终输出指定 ES2020。该警告未影响本次构建或浏览器检查。

## 本次验证

- Vite 生产构建成功，资源内联，可直接打开本地 HTML。
- Chromium 1440×900 桌面、390×844 手机实测；手机无横向溢出。
- 通过后待判断数减少、已完成数增加；修改意见提交后进入队列。
- 更大字号切换后核心正文为 21px，手机无横向溢出。
- 新想法入队、固定流程暂停和手动运行均有本地状态反馈。
- 浏览器未报告 JS 错误。

刻意没有复刻旧版七步自动播放、触发器监控、飞书卡片和电话入口：本次重点比较日常查看和判断的阅读负担。尚无真实任务后端、通知、持久化。
